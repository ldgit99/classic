질문 1

LLM 에이전트는 무엇으로 이루어지는가?

어떤 언어로 만들든, 어떤 도구를 쓰든, LLM 에이전트는 다섯 부품으로 나눠 볼 수 있습니다. 이 구분을 알면 "무엇을 고쳐야 하는가"를 훨씬 빨리 찾습니다.

부품역할고장 나면
Prompt 에이전트가 누구이고 무엇을 어떻게 하는지 알려주는 지시문 말투는 맞는데 규칙을 안 지킨다
State 턴을 넘기며 유지하는 값 — 시도 횟수, 힌트 수위, 진행 단계 매번 처음처럼 군다. 힌트가 안 올라가거나 안 내려간다
Tool 모델 밖의 일을 하는 함수 — 검색, 채점, 저장, 계산 지어낸 정보로 답한다
Knowledge 참조할 자료 — 교육과정 문서, 평가 기준, 예시 모음 일반론만 말하고 우리 맥락을 모른다
Harness 이 모두를 묶어 돌리는 껍데기 — 대화 루프, 화면, 로그 사람이 쓸 수 없거나 자료가 안 남는다

증상으로 부품 찾기

  • "자꾸 답을 알려줘요" → Prompt의 금지 규칙, 또는 State의 시도 횟수
  • "세 턴 전 얘기를 잊어요" → State
  • "우리 학교 교육과정과 안 맞아요" → Knowledge
  • "틀린 사실을 자신 있게 말해요" → Tool 또는 Knowledge
  • "대화 기록이 안 남아요" → Harness
자기점검 내 에이전트에서 다섯 부품 중 반드시 있어야 하는 것은 몇 개인가? 다섯 개 다 필요한 경우는 드물다.

질문 3

시스템 프롬프트는 어떻게 쓰는가?

교육용 에이전트의 시스템 프롬프트는 일반 챗봇의 것과 다릅니다. 하지 말아야 할 것과 그때 대신 할 것이 분량의 절반을 차지합니다.

시스템 프롬프트 골격 
# 역할
당신은 [대상]이 [과제]를 할 때 [역할]을 맡습니다.
당신의 목표는 학습자가 [학습목표]에 스스로 도달하게 하는 것입니다.
답을 알려주는 것이 아니라 학습자가 생각하게 하는 것이 성공입니다.

# 범위
- 다루는 것: [과제 범위]
- 다루지 않는 것: [범위 밖]
- 범위 밖 요청을 받으면: 한 번 안내하고 원래 과제의 마지막 지점으로 돌아갑니다.

# 대화 방식
- 존댓말, 한 번에 3문장 이내
- 한 번에 한 가지만 묻습니다
- 감탄사와 과장된 칭찬을 쓰지 않습니다

# 도움의 수위
현재 수위는 매 턴 [hint_level]로 주어집니다. 그 수위에 맞게만 응답하세요.
- L0: 개입하지 않습니다. "천천히 해 보세요." 정도만.
- L1: 방향만 가리킵니다. 질문으로. 예: "[실제 문장]"
- L2: 부분 예시를 하나 듭니다. 완성된 답은 아닙니다. 예: "[실제 문장]"
- L3: 절차를 안내합니다. 그래도 최종 답은 학습자가 씁니다. 예: "[실제 문장]"

# 금지와 대안
- 완성된 답·모범답안을 제시하지 않습니다.
  대신 → 평가 기준 한 항목을 제시하고 학습자가 스스로 대조하게 합니다.
- 학습자가 "그냥 답 알려줘"라고 하면 바로 응하지 않습니다.
  대신 → 거절 이유를 한 문장으로 말하고 더 작은 질문으로 되돌립니다.
- 학습자의 능력을 규정하지 않습니다("소질이 없네요").
  대신 → 이번 산출물의 특정 부분에 대해서만 말합니다.
- 모르는 사실을 지어내지 않습니다.
  대신 → "확인이 필요합니다"라고 말하고 확인 방법을 안내합니다.
- 실명·학교·연락처를 묻지 않습니다.
  학습자가 먼저 말하면 → 기록하지 않는다고 알리고 넘어갑니다.

# 안전
학습자가 자해·괴롭힘·위기 신호를 보이면 과제를 중단하고
담당 선생님께 이야기하도록 안내합니다. 상담을 직접 하지 않습니다.

# 현재 상태
단계: [phase]
학습자 시도 횟수: [attempt_count]
제시한 기준: [criteria_shown]
해답 요구 횟수: [answer_requests]

함정 · 추상적인 지시

"적절한 스캐폴딩을 제공하라"고 쓰면 모델은 자기가 아는 평범한 방식으로 답합니다. 수위마다 실제 문장을 넣으세요. 4주차 명세서 4.1의 "실제 문장" 칸을 쓰라고 한 이유가 이것입니다. 예시 문장 한 줄이 추상적 지시 열 줄보다 강합니다.

더 해보기 · 상태를 프롬프트에 넣기

위 골격의 마지막 "현재 상태" 절이 핵심입니다. 매 턴 현재 상태값을 문자열로 찍어 프롬프트에 끼워 넣으면 모델이 그 값에 따라 다르게 행동합니다. 복잡한 구조 없이 이것만으로도 스캐폴딩 수위 조절이 상당히 잘 작동합니다. Claude Code에게 "매 턴 상태값을 시스템 프롬프트에 주입하는 구조로 만들어 줘"라고 요청하면 됩니다.

질문 5

지식은 어떻게 넣는가?

"우리 교육과정에 맞게" 만들려면 자료를 넣어야 합니다. 그런데 자료 양에 따라 방법이 다릅니다.

자료 양방법비고
몇 쪽 시스템 프롬프트에 그대로 붙인다 가장 확실하다. 대부분 이걸로 충분하다
수십 쪽 파일로 첨부하거나 프로젝트 지식으로 올린다 Claude Projects·GPTs가 잘하는 영역
수백 쪽 이상 검색해서 필요한 부분만 가져온다 (RAG) 8주 과정에서는 대개 과잉이다

RAG를 하고 싶은 유혹

검색 기반 방식은 멋져 보이지만 구현·검증에 최소 2주가 더 듭니다. 그리고 대부분의 교육용 프로토타입은 평가 기준 한 장, 예시 다섯 개, 교육과정 성취기준 몇 줄이면 충분합니다. 프롬프트에 그냥 넣으세요. 정말 필요하다면 8주차 보고서의 "향후 과제"에 적으면 됩니다.

넣어야 할 자료 세 가지

  • 평가 기준 — 에이전트가 피드백의 근거로 삼을 항목들. 4주차 명세서에서 이미 정했다
  • 예시 — 좋은 산출물과 흔한 오답 각 2–3개. 모델이 수준을 가늠하는 데 결정적이다
  • 맥락 — 학년, 단원, 성취기준, 수업에서 이미 배운 것

지금 해볼 것 · 20분

질문 6

도구는 언제 필요한가?

도구(Tool)는 모델이 스스로 못 하는 일을 대신 해주는 함수입니다. 없어도 되면 넣지 마세요. 도구 하나가 늘 때마다 실패할 수 있는 지점이 하나 늘어납니다.

필요한 경우예
정확성이 중요한 계산채점, 점수 합산, 통계
외부의 사실오늘 날짜, 자료 검색, 사전 조회
기록을 남겨야 할 때학습 로그 저장, 교사에게 보고
정해진 절차를 반드시 따라야 할 때규칙 기반 판정

교육용에서 가장 쓸모 있는 도구 하나

로그 저장 도구입니다. 대화 내용과 상태값을 파일이나 시트에 남기는 함수 하나. 화려하지 않지만 이것이 없으면 7주차에 분석할 자료가 없습니다. 다른 도구는 몰라도 이건 이번 주에 만드세요.

함정 · 채점을 모델에게 맡기기

"이 답이 맞는지 판단해"를 모델에게 시키면 같은 답에 매번 다르게 반응할 수 있습니다. 정답이 정해진 과제라면 판정은 코드로 하고, 모델에게는 판정 결과를 어떻게 전달할지만 맡기세요. 이것이 도구를 쓰는 전형적인 이유입니다.

지금 해볼 것 · 15분

내 에이전트에 필요한 도구를 적어 보고, 각각에 대해 "이게 없으면 어떤 명세가 구현 불가능한가"를 답하세요. 답이 안 나오는 도구는 이번 학기에 만들지 않습니다.

agent-design.md 2절 기능 표와 대조. 어떤 기능에서도 나오지 않는 도구는 만들지 않습니다.

자기점검 로그 저장이 되고 있는가? 지금 파일을 열어 확인하라.
질문 7

어떻게 돌려보고 무엇을 고치는가?

"잘 되는 것 같다"는 검증이 아닙니다. 4주차에 쓴 예시 대화 네 편이 그대로 테스트 시나리오가 됩니다. 매번 같은 시나리오로 돌리세요.

시나리오확인하는 것합격 기준
정상 경로흐름이 끝까지 간다 종료 단계까지 도달하고 성찰 질문이 나온다
막히는 경로힌트 수위가 올라간다 3회 시도 후 L1→L2로 올라가고, 성공하면 L0로 내려온다
회피 경로정책이 작동한다 "답 알려줘" 1차에 거절, 2차에 L2 힌트
이탈 경로범위가 지켜진다 범위 밖 요청에 한 번 안내하고 과제로 복귀

API 키는 코드 안에 직접 쓰지 말고 환경변수나 .env 파일에 두고, .gitignore에 .env를 반드시 추가하세요. 공개 저장소에 키가 올라가면 즉시 폐기하고 새로 발급해야 합니다.

경로 C(직접 구현)로 API를 쓴다면 사용량이 요금으로 나갑니다. 테스트 중 무한 반복에 빠지지 않도록 최대 턴 수를 반드시 두세요.
