# 발표 자료 골격

> 8주차 · 발표 12분 + 질의 5분 · 슬라이드 13장 내외

---

## 한 문장

> [학습자]가 [상황]에서 [어려움]을 겪는 문제에 대해,
> [이론]에 근거한 [설계원리 N개]를 도출하고
> 이를 구현한 [에이전트]가 [무엇]을 하도록 만들었으며,
> 전문가 __인과 사용자 __인에게서 [핵심 결과]를 확인했다.

세 번 고쳐 쓴 최종본:
>

---

## 슬라이드 구성

| # | 시간 | 내용 | 넣을 것 |
|---|-----|-----|--------|
| 1 | 0:00 | 제목 + 한 문장 | |
| 2 | 0:30 | 문제 상황 | 요구분석에서 나온 장면 하나 |
| 3 | 1:00 | 요구분석 결과 | 요구 목록 요약 |
| 4 | 1:30 | 연구의 자리 | 포지셔닝 문단, 공백 |
| 5 | 2:00 | **설계원리** | 원리 목록 |
| 6 | 3:00 | **근거 추적표** | 요구·문헌 → 원리 → 지침 |
| 7 | 4:00 | 에이전트 구조 | 구조도 |
| 8 | 5:00 | **시연 (2분)** | 녹화본 |
| 9 | 7:00 | 전문가 타당화 | I-CVI / S-CVI 표 |
| 10 | 8:00 | 개선 이력 | v1 → v2 대화 비교 |
| 11 | 9:00 | 사용성 평가 | 완료율 · 심각도 · 원리별 로그 집계 |
| 12 | 10:00 | 논의 | 예상과 달랐던 것, 원리 재검토 |
| 13 | 11:00 | 한계와 향후 | |

> 처음 연습하면 대개 18분이 나온다. **줄일 곳은 앞부분(1–4번)**이다.
> 설계원리와 결과에 시간을 준다.

---

## 시연 대본 · 2분

| 시간 | 보여줄 것 | 화면 |
|-----|--------|-----|
| 0:00–0:20 | 상황 설정 | |
| 0:20–1:00 | **핵심 원리가 작동하는 장면** (답 요구 → 거절 → 되묻기) | |
| 1:00–1:40 | 학습자가 해낸 뒤 힌트 수위가 내려가는 장면 | |
| 1:40–2:00 | **남은 문제 하나를 솔직하게** | |

### 준비

- [ ] 화면 녹화본을 만들었다 (실시간은 반드시 실패한다)
- [ ] 대기 시간을 잘라 2분에 맞췄다
- [ ] 소리 없이도 이해된다 (자막 또는 화면 내 텍스트)
- [ ] 개인정보가 화면에 없다

## 예상 질문과 답 (각 세 문장으로)

**Q. 이게 기존 챗봇과 뭐가 다릅니까?**
>

**Q. 학습 효과는 검증됐습니까?**
> (이 연구의 범위가 아님을 분명히 말한다 — 설계·개발과 타당화까지가 범위)

**Q. 전문가 5명이면 충분합니까?**
>

**Q. 교사가 왜 이걸 써야 합니까?**
>

**Q. 모델이 바뀌면 결과가 달라지지 않나요?**
> (원리는 모델 독립적이고, 구현은 다시 검증해야 한다)

**Q. [조원이 만들어 준 어려운 질문 1]**
>

**Q. [조원이 만들어 준 어려운 질문 2]**
>

## 최종 점검

- [ ] 타이머로 12분 안에 끝냈다
- [ ] 첫 슬라이드에 한 문장이 있다
- [ ] 시연이 기능 소개가 아니라 설계원리를 보여준다
- [ ] 한계를 스스로 말한다
- [ ] 저장소 링크를 마지막 슬라이드에 넣었다
